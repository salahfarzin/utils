# v1.2.0 — 2026-10-20

Minor release. Previous: [v1.1.0](v1.1.0.md) · Diff: `git log v1.1.0..v1.2.0`

## Features

- gRPC auth interceptors: `AuthUnaryInterceptor` and `AuthStreamInterceptor`. They check the
  access token themselves, so a call made straight to a gRPC port is checked like one through
  the REST gateway.
  - The token comes from `authorization: Bearer <token>` metadata (forwarded by the gateway)
    or the `access_token` cookie (`grpcgateway-cookie` or `cookie`).
  - The verified caller goes into the context for `GetUser` / `GetUserFromContext`.
  - Incoming `x-user-*` metadata is always dropped, even on public methods, so it can't
    name the caller on the gRPC port.
  - `PublicMethods(...)` leaves full methods (`/pkg.Service/Method`) or whole services
    (`/pkg.Service/`) open without a token. A public call that sends a valid token still
    gets the caller in the context.
  - `RequirePermissions(map[string]Permission)` refuses listed methods with
    `PermissionDenied` unless the caller holds the permission. Methods not listed need only a
    valid token.
- `NewAuthMeFunc(authURL, client)` builds an `AuthServiceFunc` that resolves a token with
  auth's `GET <authURL>/auth/me`. It decodes the gateway's encoding (int64 as a string,
  `StringValue` as a bare string or `{"value": ...}`). A `401` or `404` returns the new
  `ErrUnauthenticated`. A `nil` client means a 5-second timeout.
- Permissions: `User.Permissions` (`{resource: [actions]}`, the union of the user's role
  grants from `/auth/me`), `User.Can(resource, action)` and
  `RequirePermission(ctx, resource, action)`. `RequirePermission` returns `Unauthenticated`
  when there is no caller and `PermissionDenied` when the permission is missing.
- README section on authentication and permissions.
- Community health files: code of conduct, contributing guide, license, security policy,
  and issue/PR templates.

## Breaking changes

- `go.mod` now requires Go 1.27.1 (was 1.26.3). Consumers must build with Go 1.27.1 or
  newer.

## Notes

- `AuthMiddleware` (HTTP) is unchanged. It still forwards `x-user-id`, `x-user-uuid` and
  `x-user-roles` to the gRPC handlers behind the gateway. Permissions are not forwarded in
  headers, so `User.Permissions` is empty on a user rebuilt from those headers.
- Those headers can be trusted only as far as the gRPC port is exposed. Pair
  `AuthMiddleware` with `AuthUnaryInterceptor` on any gRPC server whose port is reachable,
  which includes ports published in docker-compose.

## Upgrade notes

- Build services that consume this release with Go 1.27.1 or newer.
- To adopt the interceptors, build one `NewAuthMeFunc` client and pass it to both
  interceptors. List the health service in `PublicMethods` (e.g.
  `"/grpc.health.v1.Health/"`) or health checks will fail with `Unauthenticated`.
- Check permissions (`User.Can`, `RequirePermission`) rather than role names. What each role
  grants is configured in auth.

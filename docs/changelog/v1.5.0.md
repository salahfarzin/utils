# v1.5.0 — 2026-11-05

Minor release. Previous: [v1.4.0](v1.4.0.md) · Diff: `git log v1.4.0..v1.5.0`

## Features

- `middlewares.TokenFromIncomingContext(ctx)` returns a gRPC call's access token. It
  finds the token where `AuthUnaryInterceptor` and `AuthStreamInterceptor` do: first an
  `authorization: Bearer <token>` metadata entry, then the `access_token` cookie
  (`grpcgateway-cookie`, as the REST gateway forwards it, or `cookie`). It returns `""`
  when the call has no token. Use it in a handler that calls another service as the
  caller, such as the AI gateway. The interceptors now use it too, so the two can't
  drift apart.
- SonarQube analysis in both QC pipelines (project key `utils`, settings in
  `sonar-project.properties`), with the tests' coverage. It runs on every branch and PR,
  each analyzed on its own, and not on `v*` tags.
  - GitHub Actions: in the test job. The quality gate fails the job; an unreachable
    server doesn't. Needs the `SONAR_HOST_URL` variable and the `SONAR_TOKEN` secret, and
    is skipped without them.
  - Azure DevOps: a SonarQube job after the tests, as auth's, that never blocks. Needs
    the `SONAR_TOKEN` secret pipeline variable, and is skipped without it.
  - Coverage is uploaded also when tests fail, so the analysis still gets it.

## Breaking changes

- `go.mod` now requires Go 1.27.3 (was 1.27.1). Consumers must build with Go 1.27.3 or
  newer.

## Upgrade notes

- Replace any local code that reads the caller's token from the gRPC metadata with
  `mw.TokenFromIncomingContext(ctx)`. Local copies that read only the `authorization`
  metadata miss the cookie: a caller signed in by cookie passes the interceptor, but
  then no token is passed on, and the downstream service refuses the call.
- The function doesn't verify the token. Behind the interceptor, the token on a
  non-public method has already been accepted. On a public method it may be missing or
  invalid.
- Upgrading a module whose `go.mod` says `go 1.27.1` raises its `go` line to 1.27.3
  (`go get github.com/salahfarzin/utils@v1.5.0` does this). Its Docker image and CI need
  Go 1.27.3 or newer. `golang:1.27-alpine` and `setup-go` with `go-version-file: go.mod`
  already provide that.
